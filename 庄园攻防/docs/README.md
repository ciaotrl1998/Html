# 庄园攻防

古风庄园经营与多方攻防对战游戏：发展产业、训练步兵与弓兵，守卫己方庄园并攻破敌方主城。游戏原名“古坊奇谭”，历史策划记录保存在同目录的《古坊奇谭_策划文档.md》；游戏内“庄园”等原有术语保留。

兵营按本营存活士兵计数，一级上限 3 人，每升一级增加 1 人，九级上限 11 人；满员停止训练且不积攒进度，阵亡后按祠堂决定的原训练速度补齐缺额。分支升级前存活的步兵仍占本营名额，各兵营独立计算，保留每庄 120 人的总上限。旧存档若已超额则暂停补兵，保留现有士兵，直到人数低于上限。步兵、弓兵基础血量均为 110，每级翻倍；在普通、无增益条件下，同等级箭塔第 5 次命中击杀。基础攻击分别为 20、11，原攻击间隔、射程和难度加成保持不变。

当前经济规则与完整价格以 [v12 双资源与交替升级费用](resource-balance-v12-2026-10-21.md) 为准：5铜钱≈1工材，祠堂、城门、箭塔逐级交替60/40价值占比；兵营从选择分支起，弓兵营每次升级固定铜钱价值60%、工材40%，步兵营固定铜钱40%、工材60%。旧存档自动换算铜钱。升级费用恢复原来的每级5倍增长及后期额外加价，产业产出仍每级翻倍。可运行 `npm run test:economy` 验证；运行 `node scripts/check-economy-v12.cjs` 重新生成价格表和隔离经济模拟。历史节奏与战斗记录见 [旧平衡报告](pacing-balance.md)，其中旧价格不再代表当前版本。

## 启动

**直接用 Chrome、Edge、Firefox 或 Safari 打开 `dist/庄园攻防.html` 即可游玩。** 这是可独立分享的离线单文件，不需要安装依赖、不需要服务器，也不会请求外部图片、字体或接口。游戏文件夹统一为 `庄园攻防/`，构建只生成 `dist/庄园攻防.html`；服务器保留旧单文件 URL 到新文件的兼容映射。存档格式与存储键不变。

也可以打开根目录的 `index.html`，此时需保留 `css/`、`js/` 和 `assets/` 中的运行资源。开发时首次执行 `npm install`，修改源码后执行 `npm run build`，同时更新兼容运行脚本和单文件版本。两个入口在浏览器中可能使用不同的本地存档空间，可通过导出/导入迁移进度。

### 本机开发与游玩副本

`assets/generated/` 整个目录仅保存在本机开发工程中，已加入 Git 忽略规则；其中的美术源图、备份、制作清单和验收截图不再随仓库分发。新拉取的副本不需要该目录，可以直接打开已提交的 `dist/庄园攻防.html`，或使用完整源码目录游玩、运行联机服务器。

正常的 `npm run build` 也不依赖该目录；本机存在美术尺寸元数据时仍严格校验，不存在时使用已提交在 `js/art.js` 中的配置。`art:*` 美术重建命令及依赖源图／旧图基准的素材测试仍限本机开发工程使用。`assets/generated/` 不再由后续 Git 提交备份，应单独备份本机开发素材；此次取消跟踪不会清理既有 Git 历史。

`npm run test:distribution` 会建立不含 `assets/generated/` 的隔离游玩副本，检查构建、源码入口与离线入口，并验证本机元数据存在时仍会拒绝损坏或不一致的配置。

单人模式和电脑合作可使用离线单文件。双人联机使用 Node.js 房间服务器，双方通过服务器网页加入同一房间。

### 双人服务器联机

将整个项目目录放在一台已安装 Node.js 的设备上（可以是同一 Wi-Fi 下的电脑，也可以是开热点的 Android 手机）。在项目目录运行：

```sh
npm install --omit=dev
npm run serve
```

服务默认监听 `8787` 端口，终端会列出局域网访问地址。两台手机加入同一 Wi-Fi 后，在浏览器里打开终端显示的 `http://局域网IP:8787`，进入“合作模式”。一人点击“创建主机”，将六位房间号告诉另一人；另一人输入房号并点击“加入主机”。房主看到队友就绪后点击“开始合作”。

也可在 Android 手机的 Termux 中运行此服务。服务器房间网页无法打开时，检查局域网 IP、设备互访和 TCP 8787 端口。更新项目后需重新启动服务，让双方刷新网页。

### 联机运行与同步

- 房主只负责创建房间、开始和重开；进入游戏后，双方都是客户端。服务器独立推进统一游戏时钟，计算敌人生成与寻路、建筑和士兵攻击、弹道命中、技能、伤害、击杀奖励、建筑修复与摧毁、波次和胜负。浏览器不运行联机战斗模拟。
- 客户端本地推进自己庄园的收益、资源显示、技能冷却和收益飘字，并立即预测建造、升级、连升和拆除。服务器校验资源与规则，为建筑分配正式 ID，再向双方广播增量；操作编号用于确认、重放尚未确认的操作以及拒绝后的回退。造化匣先显示待确认匣子，随机建筑由服务器决定。
- 对方资源余额和每秒收益飘字不广播。服务器维护双方资源账本，只在操作、奖励、经济建筑变化以及约每两秒校正时向本人发送资源与产出进度。
- 服务器约每秒运行 20 次调度，约每秒发送 10 次战场增量。消息只携带变化的建筑和单位，以及当前路点、攻击冷却、减速和定身状态，不发送完整寻路路径。双方在独立显示副本中复用士兵移动、寻路和目标选择规则，持续预测所有阵营的移动；预测不计算伤害、生成士兵或结算胜负。延迟更新先推进到本机显示时刻，再以约 180 毫秒平滑消除位置误差；偏差达到 2 格或收到完整检查点时立即恢复。未收到更新时最多预测 500 毫秒，暂停、增量缺失和队友断线时停止预测。按 ID 原位更新权威状态，保留地图、建筑与建造提示缓存。
- 可运行 `npm run test:motion` 验证移动预测、校正、状态同步，以及双浏览器中的友军／敌军移动、900 毫秒网络消息延迟与恢复、暂停和继续。
- 完整游戏检查点仅用于开局、重开、重连和增量缺失／连接积压后的恢复。任一方打开菜单、进入后台或队友断线时，共同对局暂停；菜单关闭或队友重新加入后继续。队友可重新输入原房号加入，房主退出或刷新仍会结束房间。
- 运行中的进度保留在服务器内存。房主可在暂停菜单点击“保存进度”或“导出存档”，获取服务器的完整权威存档；联机显示状态不会作为自动存档覆盖本地进度。服务器重启不保留房间，完整存档可退出联机后读取为电脑合作。

## 操作

- 打开游戏先进入开始菜单。“单人模式”新建古坊，已有存档时会提示确认替换；“读档”续接本地进度，无有效存档时不可用。“合作模式”进入等待界面，点击第二个席位可在“等待其它玩家”和“电脑队友”之间切换，也可创建或加入六位房号的服务器房间。音效开关与暂停菜单同步，并在此浏览器记住设置。停留在开始菜单或等待界面不会推进时间或自动存档，暂停菜单可保存并返回开始菜单。

- 合作模式新局随机使用 25 格宽×40 格高或 40 格宽×25 格高地图，分别对应上下或左右排列的两座庄园。除共同边界拉直外，庄园沿用单人模式的随机轮廓与地形；两庄共用一道封闭围墙，无间隙，共墙不设城门，每庄保留三个外侧城门。协防方向的城门向交界处靠近。玩家只能经营自己的庄园，队友可由另一台手机操作，或由现有托管策略接管；界面可定位到“我的庄园”或“队友庄园”。双方资源、产业上限、造化次数、祠堂与城门升级、技能冷却独立，击杀奖励平分，守夜奖励各领一份。防御建筑与士兵攻击同一战场上的敌人，任一祠堂失守即结束本局。电脑队友随暂停、后台切换和读档正确停止或恢复。

- 合作敌袭每波总数为同日单人的两倍，生成周期内成对出兵。上下排列时从“左侧”“右侧”“上下同时”三项中等概率抽取；左右排列时从“上侧”“下侧”“左右同时”抽取。两侧同时来袭时各分一半，每侧仍从地图边缘中央五格生成。共同防御同一侧时，敌人出生便轮流分给两庄该侧城门；分侧来袭时各攻对应庄园的外侧门。妖将也各分一名。敌人重新寻路、城门破损后仍攻击分配的城门，破门后进入该庄园；旧存档中的敌人首次寻路后固定目标。每七夜也遵守三选一规则。矩形合作存档为版本 7，版本 6 的 40×40 合作旧存档、早期版本 7 的 25×50 / 50×25 存档均保留原地图，单人旧存档也可继续读取；体验 25×40 / 40×25 地图需新建合作对局。

- 点击空地：打开统一建造栏，点击建筑卡片直接建造。每次切换或重新选择地块时，可建卡片排在前方；同一可建状态内依次排列高阶产业、低阶产业、防御建筑、造化匣。之后资源变化只会让卡片原位解锁，不会立即重排。地形不符和缺少相邻前置的建筑不显示，其他不可建卡片会标注原因；资源不足仅将对应资源数字标红，不显示文字提示。
- 点击建筑：查看属性、升级或拆除。祠堂不能拆除。
- 拖动地图移动视角；鼠标滚轮或双指缩放。视角拉高、缩放低于 0.9 倍时，显示“你的庄园／队友庄园／敌方庄园”标签，隐藏建筑名称；视角拉近、缩放达到 0.9 倍时，隐藏庄园标签，显示建筑名称。地图上的城门不显示方位、名称或毁损文字，用图素表示，详情面板仍保留方位以便辨认。建筑等级始终显示，可升级时显示同步上下浮动的亮黄绿色箭头。
- 本庄建筑脱战 10 秒后自动修复，速度由本庄共享城门等级决定：一级每秒恢复最大耐久的 2%，每级增加 0.2 个百分点，十五级为 4.8%/秒。四座城门不重复叠加，友方与敌方庄园分别计算；城门升级面板显示当前及下一级修复速度。受干旱影响的农田、敌兵压制下的破损城门仍遵守原有修复限制，回春诀仍直接修复 35% 最大耐久。
- 底部卡片横向滑动，电脑也可以按住拖动。
- 时间右侧 `Ⅱ` 暂停并打开菜单，关闭菜单或点击“继续游戏”恢复。固定 1 倍速，无加速按钮。空格打开/关闭暂停菜单，Esc 关闭菜单或建筑面板。
- 夜间点击右下角神技按钮施法。箭塔、擂石台和兵营自动攻击；建造、升级和拆除在白天与夜晚使用同一规则。
- 暂停菜单提供音效、保存进度、存档导入导出和重新开始。
- 暂停菜单点击“启用托管 · 电脑游玩”后立即恢复游戏，由本地电脑策略按正常资源、建造、升级与技能规则自动经营防守，不修改数值。画面显示最近操作，再次打开菜单可关闭托管并手动接管。打开菜单或切到后台会暂停；七夜胜利后继续跑测，失守后停止。新建、读档、导入或返回开始菜单后默认关闭。菜单及失守界面可导出 JSON 托管报告，包含地图种子、累计托管时间、操作次数、最近 2000 条操作和结束时存档；报告只统计当前页面中的本局托管，刷新或换局前请先导出。

主画面按顺序显示铜钱、工材，另有时间和一个暂停菜单按钮；建筑面板与神技按需出现。电脑也显示居中的手机竖屏，不显示教程卡片、玩法提示、视角控制按钮或地形网格。

## 已实现

- 托管按新增收入与资源成本比较产业扩建、升级，允许在数量上限及间距规则内重复建造同类产业；预留产业链连接位置与入夜应急预算。防守按来袭方向、现有火力和城门压力补强，已有箭塔足够时继续发展经济，不预先铺满八塔；火力不足时优先升级已有防御。托管报告中的 `income-pressure-v2` 策略为每次操作记录决策原因。

- 新局使用第二版 25×25 地图生成：河流随机位于四个方向，起止位置与弯曲路径随机；全图随机生成 1～3 处独立湖泊，山林位置、数量与形状随机。庄园的四侧边界、尺寸与轮廓随机，四座城门随边界移动。保留中央 5×5 起始平地、基础产业所需地形、封闭城墙及四门连通道路。地图生成版本随存档保存，旧存档继续使用原来的地图与城门；体验新版需选择“单人模式”新建古坊。

- 17×17 固定地形地图，包含平地、水岸、水域、林地和山地。水岸由水域外围八向相邻的地格形成，有独立的浅沙色外观；水域禁止建造任何建筑，农田可建在水岸，或与水井相邻 1 格的平地。林地的产业建筑仅可建桑园，山地的产业建筑仅可建石场，其余产业向平地或水岸延伸；防御、民生和神庙不受这条限制。相邻含斜角（对角格距离按 1 计）。
- 非水岸农田失去最后一口相邻水井后，每秒损失最大耐久的 5%，期间不受白天自动修复；耐久耗尽即被摧毁。补建水井可停止掉耐久，水岸农田不受影响。
- 读取旧存档时，原先建在水中的建筑会迁往最近的空闲陆地，农田优先迁到水岸，等级和资源进度保留；如所有可用地格已满，则保留原建筑并提示。
- 全部 24 类建筑：四条三段产业链、两栋终极建筑、防御、辅助、神庙与造化建筑。祠堂最高 Lv.15，其他建筑最高 Lv.9；建造栏提供 17 类可直接兴建的建筑，另有 6 类仅能从造化匣获得。
- 八向相邻前置、等级传递、Lv.1–9 数值升级；普通建筑 Lv.2/3/4/5/6/7/8/9 分别要求祠堂达到 Lv.2/3/5/7/9/11/13/15。普通建筑 Lv.1–3、4–6、7–9 分别复用一、二、三阶段外观。建成后不再依赖前置存活。
- 点开已建建筑时，仅显示它与前后相差一级的产业建筑之间的淡色直虚线；终极建筑只连指定的产业终点。范围框只对范围大于 0 的产业建筑、水井和土地庙显示。点击箭塔会显示圆形射击范围，半径为 4 + 0.35 × (等级−1) 格；关闭详情后范围显示消失。
- 每种产业建筑有建造范围（茶肆/石场 1，农田/桑园 0，磨坊/织坊 1，客栈/瓷窑 2，钱庄 3，酒坊/成衣铺 2，商号 3，汇财会馆/百工院 4）：范围内不可再建相同建筑；范围内只有直接前一级产业按 `+10% × 2^(前置等级−1)` 提供收入增益，跨两级无加成。两座终极建筑只受各自指定的终点建筑增益。
- 产业有数量上限：农田、桑园各 8 座，茶肆、石场各 6 座，中段各 3 座，终点各 1 座，汇财会馆、百工院各 1 座。建造卡会显示当前数量与上限。
- 汇财会馆必须紧邻钱庄与酒坊，生产铜钱并使全镇铜钱收入 +5%；百工院必须紧邻成衣铺与商号，生产工材并使全镇工材收入 +10%。建造前置建筑 Lv.1 即可；终极建筑升级时，两种指定前置都必须达到目标等级。
- 商链、农链产铜钱；丝链、工链产工材。生产建筑采用交叉资源升级：产铜钱建筑以工材为主要费用，产工材建筑以铜钱为主要费用，初级建筑完全使用对侧资源。各阶段首升按对侧产业满建基础产值的 7.5 秒定价；产值每级 ×2，升级价每级 ×5。茶肆、石场单体高产且较贵，农田、桑园单体低产且较便宜。
- 水井使相邻农田收入 +20%，戏台使全镇收入 +3%；土地庙为 3 格内建筑减伤，道观增强全镇防御建筑攻击。钟馗像每 12 秒使当时场上的全部怪物减速 4 秒，基础减速 40%，随等级提高并封顶 65%。这五者及擂石台只能由造化匣获得。
- 造化匣卡片描述为“变化为随机建筑”。首次消耗 90 铜钱、60 工材，每开启一次，下一次费用按当前费用的 1.8 倍向上取整。匣子只会化为防御、辅助或神庙建筑，不生成任何生产建筑或祠堂；结果等级等于当前祠堂允许的普通建筑最高等级。
- 升级按钮固定显示目标等级及铜钱、工材图标和所需数字，不显示资源名称或“还差多少”；不足的资源数字标红。
- 每栋产出建筑独立计时，每满 1 秒结算一次铜钱或工材。
- 建筑卡片和详情把每秒产出拆为基础值与绿色加成，例如“铜钱 +10（+3）/秒”或“工材 +5（+1）/秒”；数值四舍五入、最多保留一位小数，加成为 0 或显示时舍入为 0 则省略括号。
- 每次结算在对应建筑上方显示“+数额＋资源图标”，向上飘动并淡出。小数收益保留到后续结算，飘字整数与实际到账一致。
- 白昼 72 秒、黄昏 8 秒、夜间清完波次后入晓；白天每秒修复 10% 最大耐久。
- 加权格子寻路、绕开水域与拆墙、建筑受损及毁坏、三类敌人、民兵、减速、远程与范围攻击；受损建筑的血条贴近图标上方。敌人耐久每夜 ×1.23、伤害每夜 ×1.12、移速逐夜增加且最高为基础的 1.22 倍；波次数量从首夜 10 个快速增加，最高 120 个，最低生成间隔 0.28 秒。
- 驱鬼符、回春诀、九霄天雷仅在夜间使用，不消耗资源、不要求建筑解锁，只受各自冷却限制。
- 箭塔和兵营可直接建造；擂石台、土地庙、水井、戏台、钟馗像和道观仅由造化匣获得。保留发展成就奖励，不显示引导任务；每 7 日灯会、收益加成与妖将来袭。
- 祠堂失守结束游戏；守过第七夜展示阶段胜利，可继续经营。
- 本地自动存档、存档校验、导入导出；页面隐藏和打开菜单时暂停计时。无离线收益。
- 自绘 Canvas 中式建筑与地形、昼夜色调、弹道及神技效果、可选合成音效。

## 原型数值约定

初始资源为 200 铜钱、120 工材；商链和农链各段基础收入为 1/3/6 钱每秒，丝链和工链为 2/5/9 工材每秒，祠堂基础收入为 0.4 钱每秒。每级产出、攻击和辅助增益为上一级的 2 倍，耐久为上一级的 1.55 倍；产业加成总量上限 +200%，每七日灯会另外提高当日收入 25%。土地庙基础减伤 20%，范围 3 格，叠加上限 65%；道观基础攻击增益 15%，叠加上限 150%；钟馗像每 12 秒全体减速 4 秒，减速率从 40% 起并封顶 65%。驱鬼符定身全部来敌 4 秒并造成 20 伤害；回春诀修复全部建筑 35%；九霄天雷全图造成 240 伤害，对阴兵造成 350。

两座终极建筑分别要求相邻指定的一对产业终点，Lv.1 即可；相邻含斜角。

地图完整开放，扩张通过继续占用地块进行。`node scripts/balance-sim.js 15` 可重跑抢建产业、产业优先升级、兼顾防守三条固定路线；自动化回归还会用 5 个种子验证主动防守路线。当前基线中，无视防守会在第 2 夜失守，主动发展、升级与施法可稳定守过第 15 夜，但不保证继续无损推进。

`build.js` 通过 esbuild 将脚本转换为 ES2017，生成 `js/runtime.js` 和 `dist/庄园攻防.html`，并同步兼容旧文件名入口。规则与网络协议测试不依赖浏览器，联机浏览器测试使用两份隔离的手机视口会话。网络回归覆盖服务器自主运行、操作预测与拒绝回退、资源隔离、击杀去重、原位增量更新、缓存复用、房主主线程阻塞、暂停、存档、重连和重开：

```sh
node --test tests/game.test.js
```

浏览器回归测试使用 Playwright，验证电脑与手机布局、真实鼠标点击、触摸缩放、建造升级、存档和夜战神技：

```sh
npm install
npm run test:browser
```

浏览器测试默认使用 Windows 标准位置安装的 Chrome，可通过 `CHROME_PATH` 指定浏览器可执行文件。截图默认写入系统临时目录的 `gufang-screenshots`，可通过 `GUFANG_SHOTS` 修改。测试会使用独立浏览器上下文，不操作玩家的真实存档。

### 安卓白屏修复

旧版容器只有 `height: 100dvh`，且子元素全为绝对定位。在不支持 `dvh` 的安卓浏览器中，该声明失效后容器高度变为 0，`overflow: hidden` 会裁掉整个地图和界面。已在浏览器模拟中复现这一情况。

现在采用 `100vh` 后备高度，并由兼容启动脚本使用可视区域的像素尺寸设置容器；相机和触控使用容器内坐标。移除了原生 `dialog.showModal()`、`Object.hasOwn()` 和 `Blob.text()` 依赖，运行脚本转为 ES2017。自动测试覆盖不支持 `dvh`、无 `visualViewport`、无原生 dialog 和旧存档迁移的组合环境。这里是兼容性模拟验证，并非在用户的安卓真机上测试。

存档仅存在当前浏览器中。移动文件路径、清除浏览器数据或更换设备前，建议通过菜单导出 JSON 备份；导入成功会覆盖当前进度，并尽力在本地保留导入前备份。
