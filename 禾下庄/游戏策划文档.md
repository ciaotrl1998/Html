# 古风轻量经营游戏策划案

版本：规则稿 v1.2

状态说明：正文以已确认玩法为基线；多配方自动处理和毛料链解锁已确认。动物只作为视觉表现，不是独立实体；养殖升级提高生产量与输出容量，不增加动物数量。第9节为完整的升级原型配置，数值尚需试玩验证。其他标注“建议”或“原型值”的内容仍需测试或确认。本文不包含程序实现。

## 1. 游戏定位

- 类型：中国古风、轻量模拟经营、自动化生产与物流。
- 平台：竖屏手机，优先单手操作。
- 画面：纯2D俯视格子地图，参考《环世界》的空间表达，不引入其复杂生存系统。
- 模式：单人，以及2～4人同图独立经营。
- 目标：持续付清上涨的租金，积累金币，最终买下自己的地块。
- 单局：目标15～20分钟，可通过原型测试调整。
- 玩家主要操作：建造与调整布局、雇佣与指派村民、升级、必要时赠送资源或求助。
- 体验原则：默认自动工作，不要求玩家逐次指定运输、逐批启动生产或逐只管理动物。

一句话概括：在一块租来的庄田上布置产业，村民自动生产、加工和售卖，按时付租，最后买下土地。

## 2. 核心循环与节奏

建造基础设施 → 指派村民 → 获取金币及材料 → 开启养殖与加工 → 提升产业效率 → 支付租金 → 扩张 → 买地通关。

经营判断主要来自三个问题：建新设施还是升级旧设施；增加生产还是改善运输；现在扩张还是保留现金付租。

建议节奏：

| 阶段 | 玩家体验 | 主要内容 |
| --- | --- | --- |
| 开局 | 快速看到小人工作和收入 | 里正宅、2名村民、低价采集建筑及工坊 |
| 第一轮租金前 | 建立材料来源 | 木石采集、工坊转材料、基础售卖 |
| 中期 | 建立加工链并改善物流 | 农田、养殖、加工、市场专职搬运 |
| 后期 | 收益与上涨租金竞速 | 建筑升级、全体村民升级、积累买地资金 |

不增加饥饿、睡眠、疾病、战斗、天气灾害、逐只动物繁殖或道路铺设。

## 3. 世界与地块

### 3.1 地图组织

- 所有联机玩家位于同一张大地图，各自拥有独立地块。
- 地块边界用栅栏明确围起，设置出入口。
- 房间开局随机分配不同面积的地块；地块不在局中自动变大。
- 玩家只能建造、移动、拆除和指派自己的设施与村民。
- 村民物流仅在所属玩家的产业和市场之间运行，不跨玩家生产线取料。
- 场外市场是固定建筑或地图边缘销售点，玩家无需建造。
- 建议每个地块到销售点采用相近的有效路程，防止随机位置形成过大收益差异。

### 3.2 地块平衡

已确认：小地块买地价格较低、大地块买地价格较高，目标是使平均通关时间接近。

建议以实际可建面积而非含装饰的总面积计算地块等级。所有地块保证容纳完整基础链及通行空间；租金曲线、初始资金是否随地块调整，需原型验证，不直接按面积倍增。

### 3.3 放置与移动

- 不需要铺道路；村民使用可通行空格寻路。
- 建筑免费移动；拆除返还部分费用，返还比例待定。
- 建造和移动不能封死核心出入口或其他建筑的交互位置。
- 建议拖动阶段只显示预览，确认后才改变世界状态。
- 建议实际移动时暂停该建筑任务，保留库存，重新计算相关路线；有村民交互时延迟到安全时点完成，不复制或丢失物料。
- 拆除前显示退款，未运走的实体库存保留在原位置的临时料堆，由村民自动收集出售；退款比例待定。建议市场村民优先收集，原建筑村民在转为空闲前完成拆除清运，避免无人能够处理料堆。

## 4. 三种经济对象

必须在文案、图标和程序概念中区分金币、材料、物料。

| 对象 | 表现 | 来源 | 用途 | 可赠送 |
| --- | --- | --- | --- | --- |
| 金币 | UI数字 | 里正宅被动收入、市场出售 | 雇佣、租金、买地、前期建筑、升级 | 是 |
| 材料 | UI数字 | 工坊加工木头或石头 | 中后期建筑、升级 | 是 |
| 物料 | 世界实体及建筑库存 | 各生产建筑 | 生产输入、加工、运到市场出售 | 否 |

- 雇佣、租金、买地只消耗金币。
- 采石场、伐木场、工坊等前期建筑只用金币建造，价格较低。
- 中后期建筑主要消耗材料；每座建筑是否附带金币费用由配置决定。
- 建筑和村民升级都消耗金币与材料。
- 木头、石头、谷物、蛋、粪便、肥料和加工成品等物料全部可以直接出售。
- 物料加工后售价更高，但盈利必须结合原料总价值、加工时间和搬运成本评估。
- 材料不是现实付费货币，当前方案不包含充值、广告或付费加速。

## 5. 初始建筑：里正宅

- 每位玩家开局自带，不可拆除。
- 作为地块管理、雇佣和相关升级的核心入口。
- 不占用村民，不需要物料输入，不参与实体生产链。
- 每秒无条件获得一定金币，升级提高金币收入。
- 无血量、攻击或保护任务。
- 允许免费移动，但不能拆除，移动不改变地块归属。

里正宅定位为经营保底而非独立通关手段。建议后续租金增速高于仅升级里正宅所能维持的净收入；升级回本时间不能明显优于所有生产链。

背景建议：玩家受托经营一处租来的庄田，里正宅作为当地管理宅院。名称保留古风表达，不强调严格历史官制模拟。

## 6. 建筑与生产链

### 6.1 所有普通生产建筑的通用规则

- 建造完成后仍需要指派村民才会生产。
- 一个建筑可指派多个村民，同时最多1人承担生产。
- 生产者必须位于建筑的有效工作位置。
- 输入足够、输出空间足够、有生产者在场时持续生产。
- 增加村民只提高物流能力，不直接提升生产速度。
- 输出为可见物料，生产按周期完成批次，不要求每秒生成独立实体。
- 每座建筑具有独立的输入容量、输出容量、周期与配方。
- 输入与输出缓冲满载时分别禁止新入库与新产出，禁止丢弃溢出物料。
- 生产输出超出剩余空间时，不开始该批次。
- 建议输入在批次开始时消耗，输出容量同时预留；生产者临时离岗则暂停进度，重新有人在场后续作，不重复扣输入。

### 6.2 建筑清单

| 建筑 | 输入 | 输出 | 功能与说明 |
| --- | --- | --- | --- |
| 里正宅 | 无 | 数字金币 | 基础被动收入，特殊建筑 |
| 伐木场 | 无 | 木头 | 前期基础物料来源 |
| 采石场 | 无 | 石头 | 前期基础物料来源 |
| 工坊 | 木头或石头，可混合 | 数字材料 | 建设资源转换，不输出可搬运材料 |
| 农田 | 无；肥料可选 | 谷物 | 饲料来源，肥料提高产量 |
| 养鸡棚 | 谷物 | 鸡蛋、鸡粪 | 2×2格，升级提高产量与输出容量 |
| 养鸭棚 | 谷物 | 鸭蛋、鸭毛、鸭粪 | 2×2格，升级提高产量与输出容量 |
| 兔棚 | 谷物 | 兔毛、兔粪 | 2×2格，升级提高产量与输出容量 |
| 堆肥厂 | 动物粪便 | 肥料 | 建议统一粪便配方，减少种类理解成本 |
| 腌制厂 | 鸡蛋或鸭蛋，按配方分别处理 | 鸡蛋产皮蛋；鸭蛋产咸鸭蛋 | 鸭蛋不能制作皮蛋，咸鸭蛋单件售价低于皮蛋 |
| 纺织厂 | 鸭毛或兔毛，按配方分别处理 | 鸭毛产羽绒；兔毛产毛绒 | 两种毛料不能像工坊木石一样混合计数 |
| 织染坊 | 羽绒或毛绒 | 冬衣 | 两种中间物料各自有完整配方，不要求同时具备 |
| 市场 | 各类可售物料 | 数字金币 | 固定场外出口，无需生产者 |

采集建筑持续生产，不要求寻找树木、矿脉或管理资源耗尽。树木和石块可以用于场景表现，不构成额外资源限制。

动物仅为养殖棚内的视觉动画，不是独立世界实体，不参与寻路、碰撞、库存或独立生产结算。动物可以在棚内表现为随意活动，但由建筑整体结算产物，不逐只购买、治疗或繁殖。升级不增加显示动物的数量，只提升建筑生产量和输出容量。

### 6.3 工坊混合输入

木头和石头对工坊等价，不选择配方，不要求两种同时具备。

例如原型配方可为：2单位木石输入 → 1单位材料。允许2木头、2石头或1木头加1石头完成同一批次。实际比例待定。

工坊输入仓记录真实物料种类，但配方按合计单位判断是否足够。生产完成后直接增加玩家UI上的材料，不产生需要搬走的实体输出，因此也不会因为“材料输出仓满”阻塞。

### 6.4 解锁关系

已确认采用以下基础关系，并允许后续调整：

- 里正宅自带；采石场、伐木场、工坊开局可建。
- 拥有采石场后解锁养鸡棚。
- 拥有伐木场后解锁养鸭棚。
- 拥有工坊后解锁兔棚。
- 加工建筑按对应生产建筑解锁，而非按收租轮次。

农田开局可建，避免养殖解锁后没有饲料；任意动物棚解锁堆肥厂，任意产蛋棚解锁腌制厂。解锁只判断已建成，不要求有人工作；一旦解锁本局不再因拆除前置而锁回。

拥有养鸭棚或兔棚后解锁纺织厂，拥有纺织厂后解锁织染坊。

肥料是可选增产项，缺肥不影响基础谷物生产，避免农业与养殖互相依赖造成开局死锁。

### 6.5 养殖差异与完整加工链

```text
农田 → 谷物 → 养鸡棚 → 鸡蛋 → 腌制厂 → 皮蛋 → 市场
农田 → 谷物 → 养鸭棚 → 鸭蛋 → 腌制厂 → 咸鸭蛋 → 市场
养鸭棚 → 鸭毛 → 纺织厂 → 羽绒 → 织染坊 → 冬衣 → 市场
农田 → 谷物 → 兔棚 → 兔毛 → 纺织厂 → 毛绒 → 织染坊 → 冬衣 → 市场
各动物棚 → 粪便 → 堆肥厂 → 肥料 → 农田
```

- 鸡偏向短链、高价值蛋加工；鸭的咸鸭蛋较便宜，但额外提供鸭毛，可延伸冬衣产业；兔提供另一条毛料来源。
- 羽绒指鸭毛的加工产物，鸭绒在本方案中为羽绒的同义称呼，库存和UI统一使用“羽绒”。
- 羽绒和毛绒都是可搬运、可直接出售的实体物料，不是数字材料。
- 冬衣统一为一种成品，不额外区分两套库存；两种配方的投入数量和周期可以分别配置。
- 所有中间物料沿用统一物流规则：有可用下游先加工，没有接收空间则出售。
- 多配方建筑仍同时只有1人生产，不因接受多种输入而并行运行两条生产线。
- 自动配方调度：选择库存中足够完成一批的配方，有多个配方时按等待先后轮流处理，批次中途不切换；玩家无需手动选配方。腌制厂、纺织厂、织染坊的不同配方输入分别记录，不错误混合。
- 平衡时不能只比较蛋价：鸭额外产毛，需计入总产值、饲料消耗、周期和运输量，避免鸭全面优于鸡。

## 7. 村民系统

### 7.1 雇佣与指派

- 开局2名村民，后续只花金币雇佣。
- 通过建筑面板指派或移除村民，无需拖拽小人。
- 村民只能归属一个建筑或市场。
- 普通建筑的村民只执行与所属建筑输入、输出有关的任务。
- 空闲未指派村民不擅自服务其他建筑，避免隐含的全局搬运规则。
- 系统自动选择1名合适村民生产，其他指派村民运输。
- 仅1人时，离开搬运即暂停生产；返回且条件满足后继续。
- 多人时，只要能生产，尽量保留1人在岗。
- 当建筑缺输入或无输出空间、生产者也无法工作时，允许其参与相关物流。
- 村民人数上限及单建筑人数上限待定，不增加住房需求。

### 7.2 搬运表现与升级

- 默认最多搬运5单位物料。
- 物料堆在头顶，能直观看到种类与数量。
- 建议每趟搬一种物料，减少表现及配送歧义。
- 高载重时采用少量可见堆叠加数字，不能把几十个图标堆出屏幕。
- 到达建筑交互位置自动交货；到达市场销售点自动换金币。
- 全体村民分别升级载重和速度，两项各有一个按钮。
- 升级费用随等级指数递增，例如基础费用×增长系数的等级次方；金币和材料分别配置。
- 不采用逐名培养，不加技能树或装备。

## 8. 自动物流规则

### 8.1 最新确认的规则

下游缺输入时可以主动取料；上游有产出时也可以主动送料。双方不是独立抢货，而是通过共享任务与预留决定本次由谁完成。

已采用最终选项：当前没有下游能接收的物料可以出售，不必等自身输出仓满。这覆盖早期讨论中“必须无下游或自身满仓才卖”的旧规则。

### 8.2 可用下游

一个下游只有同时满足以下条件才可接收：

- 属于同一玩家，已建成且可通行。
- 有至少1名村民指派，不要求生产者此刻已经到岗。
- 配方接受该物料。
- 输入仓扣除已预留入库量后仍有容量。

没有指派村民的加工建筑视为不存在。下游当前在生产、输出满或缺另一种输入，并不自动禁止接收；是否可接收以输入容量为准。

### 8.3 普通建筑村民优先级

1. 保证当前能够生产时有1名生产者留岗。
2. 运输村民优先补充所属建筑的输入。
3. 当前没有可执行补料任务时，搬运所属建筑输出，优先送可用下游。
4. 当前没有可用下游接收该批物料时，送市场出售。
5. 无任务时等待，不转为其他建筑的通用村民。

建议输入补充使用简单目标水位，例如下一批所需量或一个搬运批次，避免无限补满挤占输出运输。实际水位通过测试确定。

### 8.4 市场专属村民

- 市场可指派多个村民，不需要驻场生产者。
- 从所属玩家的全部生产建筑收集可售物料，运到市场出售。
- 可售条件与普通村民一致：当前没有可用下游能接收的剩余数量。
- 优先清理满仓或阻塞生产的建筑，再按就近顺序取货。
- 有下游可接收的数量先预留给加工，剩余才生成售卖任务。
- 未指派市场村民时，各建筑仍可自行售卖；市场指派是提升物流效率，不是售卖前提。

例：鸡舍有5枚未预留鸡蛋，腌制厂只剩2格接收空间。2枚可以分配给加工，剩余3枚可出售；不能因存在一个下游就全部锁住，也不能把可加工的2枚优先卖掉。

### 8.5 任务与库存协同

这是内部规则，不展示为玩家需要维护的“物流网络”。

- 统一记录实际库存、可取数量、入库预留、在途物料、任务归属和目的地。
- 创建任务时同时预留源端物料及目的端容量，之后才派村民出发。
- 上游送货和下游取货合并为同一运输需求，一个需求不能重复认领。
- 源端被预留的库存不能再被另一村民取走或用于另一任务。
- 市场售卖任务也必须预留源端物料。
- 接单后目标状态短暂变化不反复取消任务；已经搬出的货物优先完成既定配送。
- 改派、移动、拆除、断线等情况下必须释放未执行预留，妥善处理已取货物料。
- 建议目标失效时先重新寻找同玩家可用下游，再送市场；不可通行则回存或原地放料，不丢货。
- 到货、扣库存、生产和售卖在同一权威端结算，禁止重复收入。

## 9. 升级系统

每座建筑仅一个升级按钮，固定升级路径，不选择分支。

| 建筑类型 | 建议升级效果 |
| --- | --- |
| 里正宅 | 提高每秒金币 |
| 伐木场、采石场 | 缩短周期、增大输出缓存 |
| 工坊 | 提高材料转换速度、增加输入缓存 |
| 农田 | 提高批次产量、增大输出缓存 |
| 动物棚 | 提高生产量与输出容量，不改变动物视觉数量 |
| 加工厂 | 缩短周期或提高处理批量、增加输入输出缓存 |

提高批量时相应提高配方输入，不能无意中使高等级配方凭空降低成本。不同建筑加成可以不同，但面板必须显示本次收益和费用。

原需求中的输入输出效率通过批次处理量和库存缓冲体现；交货自动瞬间入库配短动画，不另设装卸操作。是否加入装卸速度属性暂不建议。

### 9.1 等级与读取方式

以下为完整升级原型表，暂定所有可升级建筑为1～5级，建造后为1级。每次只升一级，不选择属性分支。表中均为该等级的实际值，不是需要再次累加的加成；金币与材料费用只在升级时扣一次。

- 生产批量增加时，配方输入按比例增加，保持转换比例不变；采集与农田无需基础输入。
- 容量以物料单位计；输入和输出仓分开计算，同仓多种物料共用总容量，不是每种各占一份容量。
- 各等级容量均大于或等于最大单批输入及输出，避免升级后无法生产。
- 工坊无实体输出仓；材料直接进入数字余额，无余额容量上限。
- 养殖棚周期固定，升级只提升批量与输出容量；输入容量同步扩大以适配新配方，不提高动物数量。
- 升级保留库存与正在生产的批次。当前批次按启动时的旧配方和周期完成，下一批才使用新等级参数；里正宅收入立即更新。
- 市场是场外公共设施，不升级，不收升级费。个人通过增加市场村民和全体载重、速度升级提高销售效率，不影响其他玩家。

### 9.8 平衡验证约束

- 5级是高投入选项，不要求每局把全部建筑升满；扩建与升级须都具有合理使用场景。
- 里正宅满级仅增加0.8金币/秒，避免低投入被动收入取代生产经营；仍需结合租金和买地价验证。
- 加工成品售价须高于该配方所消耗原料的合计直接售价，而非只高于单个原料售价。
- 建筑高等级产能增加可能导致粮食或物流不足，这应通过雇佣、载重或配套建筑解决，不能隐藏为额外人口规则。
- 表中动物产物、材料消耗比例和周期均由建筑配置决定，视觉动物动画不能修改经济结算。
- 此节数值未经实机经济模拟，正式配置前应验证首轮付租、材料获取速度、升级回本与不同地块通关时间。

## 10. 租金、求助与胜负

### 10.1 正常收租

- 同一房间所有仍租地玩家同步收租，周期固定。
- 租金按轮次上涨，不根据玩家实时现金或建筑数量临时加价。
- 到期金币足够则自动扣除，无需确认按钮。
- 建议收租间隔180秒，租金采用可配置递增表，具体金额待验证。
- 界面常驻本轮应付额和下次收租倒计时；建议最后30秒提醒。
- 地主到访可以作为动画，不影响实际结算时点，不能被寻路阻塞。

### 10.2 欠租与时间窗口

- 首次欠租：30秒宽限，其中一次求助募集10秒。
- 后续欠租：仍可求助，但只有10秒募集期，无额外30秒自救宽限。
- 欠租时自动发起求助，无其他可帮助者时仍按对应时间允许自救。
- 当欠租者自己的金币已足够时，自动完成支付并取消募集，不扣帮助者金币。
- 首次求助失败后可在剩余宽限中靠收入补足；后续募集到期仍不足即失败。
- 建议每次欠租仅募集一次，不在一个窗口内反复打扰其他玩家。
- 此处秒数为已认可的原型时间，不是最终平衡值。

### 10.3 求助窗口

- 仅对本轮已付清租金的经营中玩家出现；已买地者视为无需交租，可帮助。
- 窗口放在屏幕偏上区域，不遮地图主要操作和底部操作栏，不阻断操作。
- 内容显示欠租者身份、还差多少金币及募集倒计时。
- 下方两个按钮：帮助、拒绝帮助。
- 帮助表示同意参与统一分摊，不立即扣钱，不创建偿还债务。
- 建议提示“结算时可能使用你的全部可用金币”，避免低余额玩家误解。
- 拒绝无惩罚；募集期间欠款显示实时更新。
- 多个求助同时发生时使用一个可切换的紧凑窗口，不堆叠多个弹窗；各求助倒计时独立运行，窗口切换不暂停募集。建议按截止时间排序，并显示其他求助数量。

### 10.4 分摊与原子结算

募集结束时按欠租者当前余额重新计算缺口D，帮助者以此刻可用金币计入，不使用点击时的旧余额。

1. 若参与者余额合计小于D，全部不扣钱，判定帮助失败。
2. 若足够，先按参与人数均分D。
3. 余额不足其份额的人贡献全部余额；未补足部分在其余人间继续均分。
4. 重复至足额，整数余数按稳定顺序分配，不超过任何人的余额。
5. 一次性扣除欠租者已有金币和帮助者分摊金币，付清本轮租金。

举例：缺口120，3名帮助者余额分别20、100、100。最终贡献20、50、50。

失败文案固定为：“帮助失败：大家的资金不足以垫付欠款。”

多笔求助结算建议按固定顺序串行执行，后一笔使用扣款后的实际余额，不能对同一金币重复承诺。结算期间不允许赠送、买地等操作穿插造成透支。

### 10.5 买地与结束

- 买地价格开局明确显示，并在本局固定。
- 只支付金币，达到价格后主动点击并确认购买，立即个人通关。
- 建议未付清当前欠租时禁止买地，防止绕过到期租金。
- 通关后不再交租，可继续经营、赠送及帮助其他玩家。
- 欠租失败后停止经营，转观战，不操作资产、不赠送、不参与帮助。
- 个人通关不终止其他玩家的局，不要求全员成功。
- 建议首个通关者显示名次，之后玩家仍可完成自己的目标；是否正式排名待确认。

## 11. 联机、赠送与离线

### 11.1 赠送

- 仅支持金币和数字材料的单方面赠送，不做交换报价、物料交易或跨地块运输。
- 选择接收玩家、资源种类和数量，确认后立即到账。
- 发送者不可赠送超出可用余额的数量。
- 不需要接收者确认，不收手续费；防误操作通过发送端确认。
- 建议仅允许仍经营中的玩家互赠，观战者不参加。
- 求助分摊与主动赠送独立，但欠款必须实时重算，不能重复支付。

### 11.2 单人及联机存档

- 单人退出暂停计时、生产和收租，存档后可继续；无离线收益。
- 联机主动离开立即退出经营资格并转观战，重新加入不能恢复该局经营。
- 意外断线建议保留60秒重连窗口；期间自动生产、运输、售卖与收租继续。
- 超时转观战，停止经营；无人经营时房间结束，不保留可恢复的联机存档。
- 尚在重连保留期的玩家建议仍计入经营人数，避免全员短暂断线立刻销毁房间。
- 通关后继续经营的玩家也计入经营人数。

建议观战地块冻结，不作为他人物料来源；在途任务停止，清理任务预留。使用服务端权威房间，避免房主离开导致整局中断。技术方案需实施阶段另行确定。

## 12. 竖屏界面与操作

### 12.1 界面层级

- 顶部：金币、材料、下次租金金额与倒计时。
- 中部：地图为主体，物料、村民和动物清晰可见。
- 底部：建造、雇佣等主要入口；选中建筑后切换为建筑操作面板。
- 求助：顶部下方的非模态区域，不遮住底部操作。
- 买地：可见进度入口，详情中显示固定价格，购买前二次确认。

### 12.2 建筑面板

显示名称、等级、指派人数、生产进度、输入输出库存及单一主要状态；操作提供指派、升级、移动、拆除，不放物料去向策略或生产岗位选择。

主要状态：无人指派、等待生产者、生产中、缺输入、输出空间不足、路线不可达。地图用小图标提示，具体文字放面板，避免全屏标签。

村民指派建议用人数增减按钮配空闲人数，系统自动挑选小人；需要重新指派时可在同一面板完成。

### 12.3 操作建议

- 单指拖动浏览地图，点按选择，双指缩放作为可选操作。
- 建造选择设施后出现落点预览，确认放置；不依赖精确拖拽小人。
- 提供快速回到自己地块入口，联机查看别人地块后可一键返回。
- 控件保证手机触控尺寸，数字过长时使用明确的缩写单位。
- 不设置必须每几秒点击的收获按钮、销售按钮或生产启动按钮。

## 13. 视觉、动画与音效

- 古风田庄、木石结构、农田、栅栏与小型作坊为主体，避免现代机器造型。
- 建筑、角色与物料采用一致2D俯视风格，清晰区分占地与可通行区域。
- 动物仅为棚内循环或随机视觉动画，不创建独立动物实体，不参与村民寻路；升级不增加动物数量。
- 物料在建筑料位可见，数量多时采用堆叠表现，不将每件物料作为独立寻路对象。
- 村民头顶物料、工作动作、交货动作与出售金币反馈是重点。
- 升级反馈短而明确，不用大弹窗遮挡地图。
- 背景音轻松，生产与金币音效限频，避免大量村民产生持续噪声。

## 14. 原型参数与平衡原则

以下是待测试的配置项，不作为最终数值承诺：

| 项目 | 起始方案或原则 |
| --- | --- |
| 单局目标 | 15～20分钟 |
| 收租周期 | 180秒 |
| 首次宽限 | 30秒 |
| 求助募集 | 10秒 |
| 断线保留 | 60秒 |
| 初始村民 | 2名，已确认 |
| 初始载重 | 5单位，已确认 |
| 小型动物棚 | 2×2格 |
| 初始金币 | 足够建立至少一条采集→工坊链，并可雇佣一次或留有租金余量 |
| 初始材料 | 建议0，检验工坊链是否易启动 |
| 基础生产周期 | 按第9节逐建筑表配置，1级约8～14秒 |
| 缓冲容量 | 至少容纳完整配方批次和一趟初始搬运 |
| 升级费用 | 村民两条升级采用指数递增，倍率待定 |
| 拆除退款 | 部分返还，比例待定 |

平衡约束：

- 前期三座建筑都便宜，但不强制玩家同时建齐木、石两条线；工坊任一来源即可启动。
- 每条加工链在正常物流下应优于直接卖原料，但不是任何距离下都绝对划算。
- 工坊加工成材料是建设投入，不自动换金币；玩家可把木石直接卖掉来保现金。
- 所有地块都能容纳自给饲料与基本加工，不能因随机面积天然无法通关。
- 多村民的价值主要是让生产者少离岗、让输入输出更顺畅。
- 材料不能出现“只能材料建造工坊，而工坊又产材料”的启动死锁。
- 肥料不会成为开局刚需。
- 里正宅保底收入不能令其他产业失去意义。

## 15. 开发范围建议

### 15.1 玩法验证原型

先完成里正宅、木石采集、工坊、市场、农田、养鸡棚、堆肥厂和一种蛋加工；验证1人离岗停产与多人留岗的差异，随后验证2人联机租金互助。

### 15.2 首版完整范围

加入2～4人、不同面积地块、养鸭棚和兔棚、咸鸭蛋加工、纺织厂与织染坊两条冬衣链、前置解锁、赠送、观战、重连、完整UI及音画反馈。

### 15.3 不在本版范围

战斗、人物需求、道路加速系统、动物繁殖疾病、物料交易、科技树、分支升级、离线挂机收益、现实付费和长期养成。

## 16. 验收与试玩重点

- 开局只用金币和2名村民能建立材料来源。
- 1名村民出去搬运时停产，回到岗后恢复且不重复消耗输入。
- 2名及以上村民时最多1人生产，其他人运输，不按人数直接倍增产速。
- 无指派村民的加工厂不接收物料。
- 上游主动送和下游主动取不会抢同一货、重复预留或超出接收容量。
- 下游只剩部分容量时，先保留可加工数量，其他数量可出售。
- 市场村民与建筑村民不会重复收货或重复生成金币。
- 工坊混合木石能完成同一配方，材料直接到账且不会出现在小人头顶。
- 鸡蛋只能走皮蛋配方，鸭蛋只能走咸鸭蛋配方，咸鸭蛋售价低于皮蛋。
- 鸭毛加工为羽绒，兔毛加工为毛绒，两者能分别加工成冬衣，不能混用未满足的配方输入。
- 多配方建筑每批只运行一个配方，不错误共享进度、重复扣料或长期饿死另一条配方。
- 各等级的输入与输出容量能容纳一整批，升级保持配方比例，当前批次不重复扣料。
- 动物不是实体，升级不增加动物数量；养殖棚只按建筑表结算产量与容量。
- 升级费用逐级翻倍、各建筑独立结算；市场没有升级入口，全体村民两项升级独立生效。
- 建造和移动不能封路；改派、拆除、断线不会永久遗留预留锁。
- 所有玩家同时收租，个人成功或失败不打断其他人。
- 多人互助严格按最后余额分摊，不足则无人扣款；并发求助不透支。
- 赠送与求助同时发生不会使欠款重复结清。
- 首次及后续欠租采用不同时间窗口；没有帮助者也能按规则进入失败。
- 主动退局不恢复经营，短暂断线能恢复；全员断线不会在保留期内提前销毁房间。
- 手机上单手能完成建造、指派和升级，求助窗口不阻断操作。

## 17. 尚需最终确认的细节

以下不影响核心方案成立，但必须在正式配置及美术制作前定稿：

1. 拆除退款比例，以及临时料堆的清运人员与任务收尾方式。
2. 第9节的原型等级上限及数值平衡，村民人数上限。
3. 多人求助排序和结算顺序，个人通关是否显示正式排名。
4. 地块实际格数、租金表、买地价格、售价、肥料加成和建造价格。

这些条目应保留为可配置或明确标注的建议，不得在实现中默认为已确认规则。
