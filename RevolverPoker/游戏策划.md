## 1. 已确认的方向

开发一款手机竖屏优先的 HTML 3D 德州扑克游戏。玩家以第一人称坐在 19 世纪架空德州的酒馆牌桌旁，通过同一个牌桌流程邀请朋友联机或与电脑对战。每桌设 8 个座位，玩家点击开放空座坐下；房主入座后将其他空位切换为“开放”或“AI”，并在每场开始前设置筹码和规则。

核心目标是还原标准德州扑克。西部酒馆提供场景与氛围，不改变牌局规则；不加入特殊技能、读心线索、剧情挑战、俄罗斯轮盘、枪战或额外胜负条件。

| 项目 | 方案 |
| --- | --- |
| 类型 | 标准德州扑克；首版实现无限注德州扑克 |
| 人数 | 每桌 2–8 个参赛席位，包含真人与电脑 |
| 开局方式 | 统一进入牌桌、点击入座，由房主逐座设置“开放”或“AI” |
| 视角 | 坐姿第一人称，真实 3D 场景与角色 |
| 设备 | 手机竖屏为主，兼容电脑鼠标操作 |
| 背景 | 19 世纪架空西部酒馆，牛仔、左轮枪、木桌与灯火 |
| 筹码 | 游戏内虚拟筹码 |
| 语言 | 简体中文界面，保留必要扑克缩写 |

年代说明：德州扑克的起源通常追溯至 20 世纪初，因此本作采用架空西部背景。[背景资料](https://capitol.texas.gov/tlodocs/80R/analysis/pdf/HC00109H.pdf)；左轮枪外形可参考 19 世纪实物。[大都会艺术博物馆藏品](https://www.metmuseum.org/art/collection/search/24835)

以下数值和流程是本版策划建议，尚可在实现前调整。

## 2. 统一开局：点击座位入座

创建或加入房间 → 进入同一张八人牌桌 → 点击开放空座坐下 → 房主设置其他空位为“开放”或“AI” → 设置筹码与规则 → 房主点击开始 → 连续牌局 → 本场结算 → 回到同一张牌桌再次开场。

不设置单人、联机或混合模式选择页；参赛者构成由座位状态自然决定。创建房间与通过邀请进入房间，最终进入同一套牌桌界面。

### 入座与权限

- 创建房间的玩家成为房主，但不自动落座；初始 8 个座位均为“开放”。
- 房主与朋友都通过点击开放空座选择自己的位置；镜头随后切换到该座位的第一人称视角。
- 房主坐下后，点击其他无人空座可将其从“开放”切换为“AI”；再点击该 AI 配置座位可切回“开放”。配置发生在开场前。
- 普通玩家点击开放空座即可坐下；不能切换座位类型，也不能占用 AI 或其他真人的座位。
- 入座即表示参与下一场，不另设“准备”按钮。所有人可以直接查看房主设置的筹码与规则。
- 开场前玩家可以离座，其原座位恢复“开放”；房主离座后须重新坐下，才能继续配置座位并开始比赛。
- 不允许房主通过“开放 / AI”切换替换已坐下的真人。
- 首版采用昵称、房间码与匿名会话，免注册；房间码用于找房，不作为玩家身份凭证。

### 座位显示与点击行为

| 状态 | 显示 | 普通玩家点击 | 已入座房主点击 |
| --- | --- | --- | --- |
| 开放空座 | 空椅子、“开放 · 点击入座” | 未入座时坐下 | 自己尚未入座时坐下；已入座时切换为 AI |
| AI 配置座位 | 电脑角色预览、“AI” | 无法入座 | 切回开放，移除 AI 预览 |
| 真人座位 | 玩家角色、昵称、房主标记（如适用） | 查看公开信息 | 查看公开信息，不能切换为 AI |

AI 座位的预览表示该位置已配置电脑参赛者，并非可被真人抢占的开放空座。进入比赛后，所有参赛座位统一显示筹码和行动状态。

### 开始条件

- 房主已入座，真人与 AI 合计至少 2 人、最多 8 人，即可点击开始。
- 不要求坐满 8 人，空余开放座位不参与发牌、不支付盲注。
- 例如房主把一个空座切为 AI，即可独自开场；保留开放空座让朋友坐下，即可朋友对战；也可按座位组合真人与 AI。
- 房主点击开始后，服务器校验人数和规则，并原子锁定参赛名单与座位配置；迟到者等待下一场。
- 本场结束后保留仍在房间的真人座位和 AI 配置，房主可调整空位与规则，再次点击开始。
- 本地运行需要启动随项目提供的游戏服务；单人游玩也使用同一服务与规则引擎。

## 3. “每一局”的配置边界

为避免界面和实现歧义，区分三个概念：

- **房间**：朋友聚集的空间，可以连续举办多场比赛。
- **一场**：从大家领取初始筹码开始，到决出胜者或房主结束比赛为止。
- **一手**：从下盲注、发底牌到分配底池的完整过程。

“开始时设置筹码和规则”落实为：每场开始前统一设置，每手之间继承筹码。不会在每手开始时自动重置筹码。本场进行中不修改金额或下注规则；结算后可在同一房间调整配置，再次开场。

### 首版配置

| 设置 | 默认建议 | 可设置内容 |
| --- | --- | --- |
| 房间名称 | 西部酒馆 | 自定义名称 |
| 入房保护 | 房间码 | 可选房间密码 |
| 座位 | 8 个固定座位 | 通过点击座位配置参赛者，实际开场 2–8 人 |
| 初始筹码 | 每人 2,000 | 所有人相同的正整数筹码 |
| 小盲 / 大盲 | 10 / 20 | 自定义小盲，首版大盲固定为小盲的 2 倍 |
| 盲注变化 | 固定 | 固定；或每 N 手翻倍，N 默认 10 |
| 前注 Ante | 0，关闭 | 可设每人每手支付的固定金额 |
| 真人行动时限 | 30 秒 | 15 / 30 / 60 秒；仅一名真人参赛时另可不限时 |
| AI 座位 | 无，初始全部开放 | 房主入座后逐座切换“开放 / AI”，不单设电脑数量输入框 |
| 电脑难度 | 普通 | 简单 / 普通 / 困难 |

金额使用整数；初始筹码至少覆盖一轮个人前注与大盲。升盲仅在下一手开始时生效。升盲按当前手数计算，不受动画速度或断线时间影响。

首版下注结构明确为“无限注”，不提供无法兑现的规则开关。固定限注、底池限注、重购和中途补码可作为后续标准玩法扩展，不属于首版范围。

### 本场结束

- 首版采用统一起始筹码的淘汰桌，不允许本场中途补码。
- 筹码归零的玩家退出后续发牌；仍可留在房间查看公开牌桌。
- 最后一位拥有筹码的玩家获胜，展示本场排名与筹码统计。
- 房主可以在两手之间结束本场，展示当前筹码排名；不能中断正在结算的底池。
- 只有一名真人、其余全为电脑时，真人淘汰后可直接进入结果界面。
- 同一手多人淘汰，按该手开始时的筹码多少确定先后；相同则并列。

## 4. 德州扑克规则还原

基本流程：移动庄家按钮 → 收取前注与盲注 → 每人两张底牌 → 翻牌前下注 → 翻牌三张及下注 → 转牌及下注 → 河牌及下注 → 摊牌、分池 → 下一手。

使用一副无大小王的 52 张牌。玩家从自己的两张底牌和五张公共牌中组成最佳五张牌，可以使用 0、1 或 2 张底牌。其他玩家全部弃牌时，最后留下的人直接赢得底池；否则比较牌力，同等牌力平分，不按花色判大小。[基本规则参考](https://www.pokerstars.com/poker/games/texas-holdem/)

首版必须完整处理：

| 规则点 | 实现要求 |
| --- | --- |
| 行动顺序 | 按庄家、大小盲与当前街次计算；处理淘汰后的座位轮转 |
| 双人桌 | 庄家下小盲，翻牌前先行动，翻牌后后行动 |
| 合法行动 | 弃牌、过牌、跟注、下注、加注、全下，按状态显示 |
| 最小加注 | 按本轮最后一次完整下注或加注增量计算，不能简单翻倍当前总额 |
| 不足额全下 | 正确判断已行动玩家是否重新获得加注权；处理累计不足额加注情形 |
| 边池 | 支持不同筹码玩家全下、多层边池及各层独立获胜资格 |
| 返还 | 未被任何对手匹配的下注部分返还原玩家 |
| 牌型比较 | 正确处理踢脚牌、A2345 顺子、公共牌成最佳牌等情况 |
| 平分余数 | 不可整分的最小筹码按庄家左侧开始的顺时针顺序分配给获胜者 |
| 弃牌投入 | 弃牌玩家已投入的筹码保留在底池中，但无获胜资格 |
| 烧牌 | 翻牌、转牌、河牌前分别烧一张牌 |
| 摊牌 | 按行动顺序确定展示次序；底池获胜牌必须展示，弃牌底牌不公开 |

边池、双人桌等边界规则另参考[扑克规则说明](https://www.pokerstars.com/help/articles/poker-rules-master/229151/)。最终实现须把边界情况写成可执行测试，而非仅依赖页面演示。

下注面板统一使用“加注至 X”，并另标“本次需投入 Y”，避免把加注总额与追加额混淆。快捷下注金额必须经过合法范围裁剪。

## 5. 手机竖屏与八人牌桌

### 第一人称构图

玩家坐在长椭圆桌近端，镜头紧邻桌边，采用与角色接近的坐姿眼高；其他 7 个席位沿桌面左右与远端分布。无需在一个屏幕内看全所有玩家，通过自由转头查看桌边各人。手臂放在桌边，底牌默认扣在两臂之间的近身桌面，筹码置于旁边；按住原地翻开，松开盖回。

场景与牌桌使用真实 3D；其他玩家的昵称、筹码、行动状态与庄家 / 盲注标记使用真正的 3D 广告牌，附着在角色头顶并始终面向摄像机。公共牌与底牌均位于桌面，有圆角、厚度、牌背与牌面材质；支持发牌、翻牌和弃牌动画。自己的筹码、底池金额、倒计时和下注按钮保留屏幕界面叠加。

开场前使用同一张 3D 牌桌进行入座与配置：未入座时提供能看清八个座位的选座镜头，每把空椅子附可点击标记；入座后切到所选席位的第一人称视角。房主能看清并点击其他座位的“开放 / AI”标记，底部显示筹码规则与“开始”按钮；普通玩家显示规则与等待房主开始的状态。

```text
┌─────────────────────────────┐
│ 房间码   盲注 10/20    设置  │
│        远端对手与酒馆       │
│    对手   对手   对手       │
│ 对手                 对手   │
│    对手           对手      │
│         底池与边池          │
│       五张公共牌区域        │
│                             │
```

示意图仅表达层级；具体席位位置需在 3D 原型中验证遮挡，不能直接按文字间距布局。

### 交互与可读性

- 以 390 × 844 为设计参考，并验证宽 360–430 CSS 像素的常见手机竖屏。
- 公共牌与底牌保持在桌面固定位置。默认朝向牌桌，人物和牌张随转头自由进出画面，不要求同屏看全。花色和点数优先于装饰细节。
- 最多 7 个对手的信息牌为 3D Sprite，附着角色头部并随动画逐帧移动；转头时随场景正常进出视野，不钳制到屏幕边缘，不靠网络消息或 UI 事件刷新位置。
- 当前行动者以座位描边、名字高亮与倒计时共同提示。
- 按住底牌或底部按钮，底牌原地翻开，镜头只对准牌面，位置与视野大小不变；松开只盖回底牌，保持镜头当前朝向，手动点击 ↺ 才回正。公共牌按住靠近查看、松开返回，不弹出屏幕牌面 UI。窗口失焦、后台或操作取消也要结束看牌。点击对手可展开其公开信息。
- 允许左右 360° 环视及上下转头，松手保留朝向，通过“回看牌桌”恢复朝向；常规下注不依赖转动镜头。点击人物、标签或空椅使用 3D 射线检测，区分点击与拖动。
- 主要触控区至少 44 × 44 CSS 像素，底部考虑手机安全区。
- 加注展开面板，提供滑杆、数字输入、最小合法加注、半池、满池与全下快捷项，再确认提交。
- 所有筹码变化立即反映服务器结果；动画用于表现，不能阻塞下一位玩家接收状态。
- 电脑端保持完整竖屏构图，外围以酒馆背景补齐。

## 6. 场景与美术

场景设为“黄昏至夜晚的西部酒馆”，使用风格化写实的低面数模型、清晰材质与克制灯光。视觉参考《骗子酒馆》的围桌第一人称氛围，具体角色、模型、界面和声音独立设计。

| 部分 | 制作内容 |
| --- | --- |
| 主桌 | 磨损木制椭圆桌、暗绿桌布、八个座位、筹码与庄家按钮 |
| 酒馆 | 木梁、吧台、酒瓶、墙面告示、窗户、吊灯与少量背景桌椅 |
| 人物 | 人类牛仔与旅客，帽子、马甲、外套、胡须和发型组合区分身份 |
| 枪械 | 左轮枪作为枪套或环境道具，不进入牌局操作 |
| 配色 | 烟草棕、旧木色、暗绿、黄铜、暖琥珀灯光 |
| 动画 | 呼吸待机、看牌、发牌、推筹码、弃牌、摊牌、收池 |
| 音效 | 发牌、筹码碰撞、椅子、木地板及低音量酒馆环境声 |

同一套角色基础骨架配合服装和颜色变化服务八人桌；第一人称仅制作可见的手部与前臂。角色动画不作为判断牌力的提示，不添加表情解谜系统。

性能目标先定为典型中端手机稳定 30 FPS，较高性能设备争取 60 FPS；实际帧率以选定真机测量为准。低画质减少阴影、像素比与装饰物，保留真实 3D 牌桌和全部玩法。

## 7. 电脑对手

电脑只模拟常规扑克决策，不拥有额外能力。所有难度遵守相同的信息边界，不读取对手底牌、牌堆顺序或未来公共牌。

- 简单：基础起手牌选择，较少诈唬，对位置和底池赔率考虑较少。
- 普通：考虑位置、牌面、底池赔率、筹码深度与公开下注历史。
- 困难：在同样信息下增加胜率采样与下注尺度判断，提高决策质量。

AI 接口只接收该席位可见信息，即使在服务器内执行，也不直接传入完整牌局对象。可设置自然的短暂思考时间；计算需限制耗时，避免堵塞其他房间。

## 8. 联机与断线

### 同步原则

采用独立游戏服务器作为唯一裁判。服务器洗牌、保管底牌、验证行动、计算底池与推进流程；客户端提交行动意图并展示结果。

- 每位客户端只收到自己的底牌及合法公开信息；对手底牌在允许摊牌前不下发。
- 每个行动携带房间、手牌编号、状态版本和唯一请求编号，防止重复点击、旧消息和重发造成重复下注。
- 同一房间的操作串行处理，服务器校验身份、轮次、筹码与最小加注。
- 入座、离座、开放 / AI 切换和开始比赛也由服务器串行校验；多人同时点击同一开放空座只允许一人成功，其余客户端立即刷新座位状态。
- 配置座位要求操作者为已入座房主，且本场尚未开始；开始后拒绝迟到的入座或切换请求。
- 采用服务器时间计算行动截止时间，不信任手机本地倒计时。
- 洗牌采用 Fisher–Yates 与安全随机整数，不使用可预测的固定牌序。
- 重连时下发该玩家权限内的完整状态，不依赖补播所有动画。
- 浏览器进入后台可能中断连接；返回后恢复界面，以服务器状态为准。

### 离线与离席

- 掉线保留座位并允许凭会话令牌重连，不能凭相同昵称认领座位。
- 掉线仍按本场行动时限执行：可过牌时自动过牌，否则自动弃牌；不自动跟注或全下。
- 自动弃牌后，本手已投入的筹码按正常规则留在底池。
- 长期离线席位保留本场筹码、按正常盲注消耗，直到重连或淘汰；不擅自删除筹码。
- 房主掉线时，将房间管理权限交给另一名在线真人；发牌和裁决仍由独立服务器执行。
- 房主运行的本地服务被关闭，与房主仅关闭浏览器是两回事；本地服务停止会中断整桌游戏。
- 首版重连保证限于服务仍运行的情况。服务器重启后的整场恢复列入后续持久化扩展，不虚构恢复能力。

### 联网环境

同一 Wi-Fi 下可通过一台电脑运行服务，手机访问其局域网地址。异地朋友互联需要将同一游戏服务部署到大家可访问的服务器，生产访问使用 HTTPS/WSS。

房间码只用于定位同一个服务上的房间，不能单独打通网络。开发交付应包含本地启动说明与远程部署说明；正式部署作为实现后的独立步骤。

## 9. 技术实现建议

| 模块 | 选择与职责 |
| --- | --- |
| 客户端 | HTML、CSS、JavaScript 模块，手机触控优先 |
| 3D | Three.js WebGLRenderer，使用 WebGL 2 |
| 界面 | DOM/CSS 叠加在 3D 画面上，负责按钮与信息 |
| 模型 | glTF/GLB；资源随项目提供，不依赖运行时外部 CDN |
| 服务端 | Node.js + ws；负责房间、规则、会话和广播 |
| 客户端通信 | 浏览器原生 WebSocket |
| 规则引擎 | 独立 JavaScript 模块，与渲染和动画解耦 |
| 随机数 | 服务端 Node.js crypto.randomInt |
| 首版存储 | 客户端偏好本地保存；房间与进行中比赛保存在服务器内存 |
| 验证 | 规则单元测试、多客户端集成测试、手机真机操作检查 |

Three.js 当前 WebGLRenderer 需要 WebGL 2；不支持的设备在加载时给出清晰提示。[官方文档](https://threejs.org/docs/pages/WebGLRenderer.html)  
联机库与随机数参考：[ws 项目文档](https://github.com/websockets/ws)、[Node.js crypto.randomInt](https://nodejs.org/api/crypto.html#cryptorandomintmin-max-callback)。具体依赖版本在实现时锁定。

```text
  client/       3D 场景、界面、声音与连接
  server/       房间、会话、游戏服务

  tests/        规则与联机测试
```

此处保留策划时的结构建议；当前实现已提供 client、server、shared 与 tests 目录，具体启动与部署说明见 README.md。

## 10. 实施顺序与验收

### 阶段一：标准规则与房间基础

先完成与美术解耦的规则引擎、配置与服务器，以简单调试界面验证统一点击入座、房主切换开放 / AI，以及 2–8 人发牌、下注、摊牌与连续开局。多个浏览器与电脑席位均使用同一套房间流程。

验收重点：牌型和资金流正确，底牌不泄露，2 人与 8 人均可完整打完一场。

### 阶段二：手机竖屏 3D 原型

接入真实 3D 酒馆、八人桌、占位角色、底牌与公共牌，以及正式的竖屏下注界面。

验收重点：手机无需横屏，七名对手信息可辨识，五张公共牌清楚可读，能完成一整场联机操作。

### 阶段三：角色、动画与可靠性

完善西部人物、手部、推筹码、发牌、声音、画质设置、断线重连和结算流程。

验收重点：动画不会修改规则顺序或造成重复行动；掉线重连后筹码、底池、手牌与回合一致。

### 首版完成清单

- [ ] 同一房间固定 8 个座位，实际参赛者 2–8 人，禁止第 9 位参赛者入座。
- [ ] 仅提供统一牌桌开局，玩家点击开放空座即可入座。
- [ ] 房主入座后可逐座切换“开放 / AI”；普通玩家不能配置，真人座位不能被替换。
- [ ] 同时抢同一座位或同时提交开场、入座操作时，座位与参赛名单保持一致。
- [ ] 8 位真人、1 真人 + 7 电脑、真人与电脑混合均可开局。
- [ ] 房主可在每场开始前设置初始筹码、盲注、前注、升盲及行动时限。
- [ ] 所有真人查看同一份规则，入座即参与，由已入座房主点击开始；开放空座不阻止开场。
- [ ] 按标准规则处理下注顺序、双人桌、最小加注与不足额全下。
- [ ] 多层边池、平分、余数与无人匹配下注返还全部正确。
- [ ] 每手结算前后全桌筹码守恒，重复消息不会重复扣款。
- [ ] 玩家与 AI 均无法通过其可见状态读取对手隐藏底牌。
- [ ] 网络断开、刷新、重复点击、浏览器后台恢复均有明确处理。
- [ ] 手机竖屏拥有真实第一人称 3D 酒馆和可操作的八人牌桌。
- [ ] 提供本地启动与异地联机部署说明。

首版范围到此为止：完成一款可供朋友正常联机、也能单人对战电脑的标准德州扑克游戏。后续扩展优先考虑其他标准下注结构与保存恢复，不增加改造扑克规则的玩法。
