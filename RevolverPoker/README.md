# RevolverPoker

手机竖屏、第一人称 3D 西部酒馆中的标准无限注德州扑克。每桌 8 个座位，2–8 人开场，支持朋友联机及 AI 对手，使用同一套入座流程。

电脑网页的游戏区域固定为手机的 **1200:2652（100:221）** 比例，随窗口等比缩放并居中显示；手机端使用自身屏幕尺寸。

iPhone / iPad 的表单输入使用 16px 字号，避免聚焦时自动放大。视口尺寸会区分键盘高度与页面缩放；输入结束后延迟复核视口并恢复页面原点，保留用户主动双指缩放。

## 启动

需要 Node.js 22 或更新版本。双击 **启动游戏.cmd**：自动安装缺少的依赖，并在当前 **CMD 窗口**运行游戏服务器。请保持该窗口开启；按 **Ctrl+C** 或关闭窗口可停止服务器。

服务运行期间，直接双击目录中的 **index.html** 即可进入游戏，无需手动输入地址。本地 HTML 会自动进入本机服务页面，所有牌局、3D 资源和场景编辑仍使用原有联机服务；不是脱离服务器的离线对局。服务未运行时，入口会显示启动提示和“重新连接”按钮。安装后不依赖外部 CDN。

也可在 PowerShell 7 中执行：

```pwsh
Set-Location F:\Html\RevolverPoker
npm ci --cache .cache/npm
npm start
```

然后直接打开 **index.html**，也可访问 [http://127.0.0.1:3088](http://127.0.0.1:3088)。日志直接显示在服务器窗口中。重复启动会提示已有服务地址，不会重启或中断房间。若端口被其他程序占用，可设置 `$env:PORT=3089` 后运行 `npm start`，再打开 `index.html?serverPort=3089` 的文件 URL 或访问对应 HTTP 地址。

## Android HTML 游戏盒子

将完整游戏目录复制到手机，保留 `index.html`、`package.json`、`server`、`shared` 和整个 `client` 目录。在游戏盒中点击“建立服务器”，待成功后点击“进入游戏”。直接点击游戏图标会先连接手机本机服务；服务未启动时显示操作提示。

`client/vendor` 已包含 Three.js 浏览器引擎及许可证，游戏盒内不需要另外安装 Three.js。电脑执行 `npm ci` / `npm install` 时会自动从锁定依赖同步这些文件，更新游戏时请一起复制。游戏盒的 Node 运行时仍需提供 `ws`。

编辑器保存场景后，双击 **打包手机版.cmd**（或执行 `npm run package:mobile`），将生成 `.cache/RevolverPoker-mobile.zip`，包含当前场景、3D 引擎和服务器依赖，并核对包内场景与编辑器保存文件完全一致。将 ZIP 重新导入手机游戏盒，停止旧服务器后重新建立服务器进入游戏。电脑与手机的本地游戏目录不会自动互相同步。

页面同时使用 `vh` 回退和实际视口像素高度，兼容不支持 `dvh` 的 WebView。JavaScript 模块加载或初始化失败时会显示具体提示；3D 场景需要支持 WebGL 2 的浏览器内核。

## 场景编辑器

双击 **打开场景编辑器.cmd**，会自动启动本机编辑服务并打开 [场景编辑器](http://127.0.0.1:3090/editor)，直接进入酒馆场景，不需要创建房间。也可运行 `npm run editor` 后访问该地址。服务重复打开会复用，无需关闭正在运行的游戏。

- 点击画面中的物件或左侧列表选择；列表可搜索、按分类筛选。公共牌和自己的底牌可以整组编辑，也可单独调整。
- 搜索 **筹码堆** 可调整自己或其他座位的筹码，编辑器使用与游戏一致的交互筹码模型；搜索 **预下注** 可独立调整桌前待抛出的筹码。搜索 **弃牌位置** 可分别调整 **自己 · 弃牌位置（第一人称）** 和其他各座位的弃牌落点，选择时自动开启 **弃牌预览**，游戏中的弃牌动画会落在保存的位置。自己的弃牌落点独立于底牌和手臂的位置。预览不影响真实对局。
- 搜索 **底池** 可调整桌面底池模型的位置、旋转和缩放。**底池 · 金额** 平铺显示在底池圆圈下方，可单独调整位置、旋转和缩放，也会随底池模型一起移动；金额按服务器确认的下注实时更新。所有玩家的筹码堆按实际余额显示；盲注、底注、跟注、加注和全下的筹码会移入底池并留在桌上，跨轮累计，结算时按服务器的主池、边池和退款结果移回相应玩家。断线重连直接恢复当前筹码，不重复下注或派奖。
- 搜索 **庄家牌** 可逐座位调整庄家 / 盲注标记共用的位置、旋转和缩放；**自己 · 庄家牌 / 盲注牌（第一人称）** 用于自己的标记，可切到“玩家视角”调整。三种圆牌比原庄家牌缩小 25%，顶面分别为米白色 **BTN**、青绿色 **SB**、砖红色 **BB**，字样保持清晰。编辑器按座位轮换预览三种样式，游戏按每手实际庄家、小盲、大盲座位显示；双人局隐藏 BTN，只在共用锚点显示 SB 与 BB，多人局恢复 BTN。换手和牌局更新不会覆盖保存的位置。
- **W** 移动、**E** 旋转、**R** 缩放，使用标准红 / 绿 / 蓝三轴操作柄；支持世界 / 局部坐标、吸附和数值输入，旋转数值单位为度。
- 左键拖动空白处环绕，中键或右键拖动平移，滚轮缩放；**F** 聚焦选中物件。可切换总览、玩家视角和俯视。房屋外壳默认隐藏方便编辑，可随时开启；该显示选项不影响游戏。
- **Ctrl+Z** 撤销、**Ctrl+Shift+Z / Ctrl+Y** 重做；右侧可重置选中物件。“恢复默认”重置整个编辑场景，之后点击 **保存到游戏** 才会同步到游戏。
- **保存到游戏 / Ctrl+S** 直接更新游戏场景模块 `client/scene-layout.js`。游戏初始化同步使用保存结果，首帧即为编辑后的场景，不再额外请求或轮询布局，也不再读取失败后退回早期场景。已经打开的游戏页面刷新后使用新场景；手机运行本地游戏包时，请将更新后的完整游戏包重新导入手机。
- 视口上方的 **摄像机** 是预览开关，开启后右下角始终显示竖屏画面，选择其他物件时也会保留；开关状态会记住。预览窗口内可切换“玩家视角 / 公共牌视角”，点击其中的“编辑”选中对应摄像机，也可从列表的“摄像机”分类选择。
- **玩家视角摄像机** 与 **公共牌查看摄像机** 都支持移动轴、旋转环、精确数值、FOV、近 / 远裁剪、视锥、撤销 / 重做、单独重置及保存。公共牌摄像机随公共牌组移动，可独立调整并用于编辑器参考预览；游戏按住公共牌时立起牌张，摄像机保持不动。开始牌局后才使用玩家摄像机；等待开局时入座保持俯视。松开底牌只盖牌并保留当时视角。
- **从摄像机查看 / 玩家视角 / 公共牌视角** 实时跟随对应摄像机；回到总览或俯视可继续环绕和操作摄像机轴。**对齐当前视图** 把选中摄像机的位置、朝向与 FOV 对齐当前自由编辑视图。**摊牌预览** 可查看结算时头顶手牌和牌型的效果，不改变真实对局。

编辑器使用独立的八人示例牌局，不会修改真实房间、底牌或筹码。预览中的底牌翻开以便调整。游戏中的人物呼吸、发牌动画、座位状态和按住看牌继续正常运行。编辑服务仅监听本机回环地址，文件保存只接受本机同源请求。多人游戏服务器向所有玩家提供同一份已保存布局。

## 如何开局

1. 输入昵称，点击“开一张牌桌”；朋友输入六位房间码加入同一个服务上的房间。
2. 每个人点击“开放”空座入座，镜头切到自己的第一人称位置。
3. 房主坐下后，点击其他空座切换“开放 / AI”。AI 座位再点一次恢复开放，已坐下的真人不能被替换。
   等待开局时，再次点击自己的角色、座位或头顶标签即可起身，座位恢复开放；也可重新选择空座入座。
4. 房主在“牌桌规则”里设置初始筹码、大小盲、前注、升盲、行动时间与电脑难度。
5. 至少两位真人或 AI 入座后，房主点击“开始牌局”。无需坐满，也无需另选单人或联机模式。

一人游玩时，只需把至少一个其他座位设为 AI。开场后锁定参赛名单，开放空座留给下一场；每手之间继承筹码，本场不补码。所有人筹码归零淘汰至最后一位胜者，或由房主选择“本手结束后结算本场”。结算后“再开一场”保留座位配置。

## 手机与朋友联机

### 同一网络

电脑启动服务后，CMD 窗口会显示一个或多个 `LAN: http://地址:3088`。让手机与电脑连到同一 Wi-Fi，访问电脑对应的局域网地址，然后使用同一房间码。本地 `index.html` 默认连接当前电脑；其他设备应使用主机的局域网地址。

`localhost` 只表示当前设备，手机应访问电脑的 LAN 地址。如果连接失败，检查设备是否在同一网络、路由器是否启用访客隔离，以及 Windows 防火墙是否允许该 Node.js 服务在专用网络接入。

### 异地联机

房间码不会自动建立公网连接。异地朋友需要访问同一个已部署的游戏服务。本项目包含 Node.js HTTP + WebSocket 服务，可在支持持续运行 Node.js 的服务器上启动，再通过反向代理提供 HTTPS/WSS。静态网站托管不能独立承载本项目的牌局服务。

例如服务器设置 `PORT=3088`，使用进程管理器运行 `node server/index.js`，域名反向代理配置如下（将域名和证书替换为自己的）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3088;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 90s;
}
```

客户端会自动使用当前网页的域名和 HTTP/HTTPS 对应的 WS/WSS，无需修改代码。本次交付仅在本机运行，未进行公网部署。

## 规则与操作

- 标准 52 张牌，每人两张底牌，五张公共牌，取最佳五张比较。
- 每手开局先播放约 3 秒准备表现：前 1 秒依次放置 BTN / SB / BB 标记（双人局省略 BTN），接着 1 秒小盲入池、1 秒大盲入池；有前注时随小盲阶段一并入池。随后按原节奏停顿并发牌，发牌结束后才启动玩家或 AI 的行动计时。联机筹码与底池按准备阶段依次更新，重连沿用原进度，不重播已完成的投放或扣款。
- 顶部横排展示全部已入座玩家，包含自己的头像；头像取自游戏中的人物模型，并使用褐色旧照片效果。总筹码最大，本轮下注较小；行动前显示名字，本轮行动后在同一位置显示“已跟注 / 已加注 / 已过牌 / 已弃牌 / 已全下”。下一轮恢复名字，弃牌与全下状态保留。当前行动玩家用金边突出，弃牌和已出局玩家变暗；鼠标悬停可查看完整姓名和准确金额。结算时隐藏下注和总筹码，改为两张已公开手牌及牌型；未公开、弃牌和未摊牌手牌使用牌背，胜利玩家使用金色外发光。窄屏和多人桌会自动改用更紧凑的头像排列。
- 顶部第一行左侧显示较小的房间号，右侧显示网络状态、重置视角和设置，玩家头像状态栏排列在其下方；不显示手数和邀请按钮。顶部采用半透黑底，底缘向下渐变透明；工具按钮图形较小，保留 44 × 44 像素触摸区域。
- 每手结算后，角色头顶的 3D 广告牌展示两张手牌缩略图和最终最佳牌型名称，不展示姓名与筹码。胜利玩家的两张牌使用与下方胜利牌型展示一致的金色外描边和柔和外发光，上方金色“WIN”每秒循环从 100% 放大到 120% 再缩回，手牌和牌型名称保持不动；平分底池及边池获胜者也会标记。弃牌 / 未摊牌 / 未公开的底牌使用牌背和对应状态，不泄露隐藏信息。下一手开始后恢复正常信息。
- 对局使用桌面手势，已移除底部弃牌、跟注、加注按钮及加注弹窗。单击自己的筹码堆，将跟注所需筹码移到桌前；按住桌前筹码向前拖出并松开才提交跟注。
- 按住自己的筹码堆时才显示黄铜与暗色皮革风格的右侧 UI 滑杆，松开即隐藏；上端位于头像栏下方约 10px，下端固定在屏高约 68% 处。按住后可在屏幕任意位置上下拖动选额，横向位置不影响金额，达到上下限后反向拖动立即响应；大号金额跟随滑块显示在左侧。快速单击筹码堆仍预备跟注，滑杆顶端为允许的 ALL IN。松开后将选中的本次投入放到桌前，并显示准确金额。提交前可再次长按重新选择，按差额移入筹码或退回筹码堆；单个筹码标有面值。单击桌前预下筹码可全部收回筹码堆，金额标记随之消失；横向拖动或取消手势不会误提交。预下金额不修改服务端余额，前拖桌前筹码并松开才提交下注或加注，已提交的下注不可收回。
- 按住自己的手牌向桌面中央前拖并松开即可弃牌；按住不前拖仍可翻牌查看。连续点击两次桌面过牌，有跟注欠额时不会误触过牌。筹码、手牌手势会暂停视角拖动，空白桌面拖动仍可转向。
- 滑杆底端从当前最低可投入额开始：需跟注时为跟注额，无需跟注时为最低下注额，筹码不足时为实际可投入的全下额，不再保留 0 注区间。最低额到满池保持线性刻度；满池高于最低额且不超过可用筹码一半时仍位于中点，否则按扣除最低额后的可选范围分配位置。满池到 ALL IN 保持等比增长，相同拖动距离对应相同增长倍数。普通选额在不超过满池且不超过 100 时按 1 个筹码微调，超过满池或超过 100 时按 10 取整。节点、跟注、最低加注额及 ALL IN 保留准确整数金额。收回预下注可单击桌前筹码。
- 吸附区间外，滑块跟随拖动位置。底端跟注节点显示“跟注至少 X”，跟注额以上至最低加注额显示“加注至少 Y”，两个门槛都随实际牌局变化，中间区间保留真实刻度预览。所有门槛和池比例节点统一使用上下各 8px 的吸附范围；重合节点共用位置。例：跟注 10、满池 30 时，底端为 10，满池位于中点，两者之间按 10→30 对应数值。松手生成桌前预下注时再校正至合法加注下限，仍须前推筹码才能提交。无需跟注时，底端显示“最低下注”。
- 手机拖动从第一个像素更新选额预览，优先采用最新合并触摸坐标；滑块、填充和数值位置使用无过渡的合成层变换。每轮缓存节点与取整区间，拖动时仅重写变化的金额或提示，不重复测量布局或处理未变化的 3D 筹码，场景阴影在按住选额时复用、松手后恢复更新。预览独立于 3D 帧率设置即时更新，松手和取消立即结束预览。
- 预下金额随回合、手数、房间、连接状态变化自动清空。提交中的同一手势不会重复下注；不足最小加注额时仅允许合法的短筹码全下。
- 正确处理双人桌、踢脚牌、A2345、边池、平分余数、未匹配下注返还及不足额全下后的加注权。
- 摊牌结算时，赢家提示下显示由手牌与公共牌组成的最强五张牌，复用头顶摊牌卡面；组成对子、三条等牌型的牌使用金边，踢脚牌使用普通边框。平分或边池有多个赢家时分别展示，共用同一组公共牌获胜时合并展示。不公开未摊牌或已弃牌的手牌。
- 最终结算单只显示冠军。整场结束时先展示最后一手的赢家和成牌，完整保留 6.5 秒结果倒计时，归零后再弹出最终结算单；房主在结果展示期间结束本场时沿用剩余倒计时，重连不会延长等待。
- 大盲为小盲两倍；可固定盲注，或每 5 / 10 / 20 手翻倍；前注为每人每手固定数值。
- 公共牌与底牌均为带圆角、纸张厚度、正反面和阴影的真实 3D 模型；公共牌铺在桌面，自己的底牌默认扣在两臂之间的近身桌面，筹码移到旁边留出空间。牌面随服务器状态更新，包含发牌、翻牌和弃牌动作。
- 直接按住底牌模型，底牌原地翻开，摄像机保持不动；松开后只盖回牌。按住公共牌模型会立起公共牌并朝向玩家，松开后放回。看牌期间暂停鼠标或触屏转向。底部仅保留筹码、行动状态和计时，不显示操作按钮。
- 发牌和阶段等待期间仍可按住自己的底牌查看；已开始按住的底牌不会因翻牌、转牌或河牌被自动盖回。尚未到手的牌保持原发牌动画，到手后再翻开；松开、取消或失焦仍会盖牌。发牌期间下注、过牌和弃牌继续锁定，期间开始的看牌手势也不会在发牌结束后误触弃牌。
- 松开鼠标或手指、操作取消、窗口失焦或切入后台时，都会结束看牌并盖回底牌。转头时牌张留在桌面，不跟随屏幕移动。点击对手显示其公开信息。
- 等待开局时保持俯视，入座只添加角色，不旋转牌桌或切换摄像机；按住拖动可水平转动约 ±17°、垂直约 ±3.2°，外侧逐渐增加阻力，反向拖动立即响应。松手、移出画面或切换窗口后保持当前角度，不自动回弹；点击 ↺ 或 Home 可复位。开始牌局后，已入座玩家才切换到保存的第一人称摄像机，重新开局回到等待阶段时恢复俯视。
- 电脑端按住鼠标左键拖动转向，触屏设备按住画面拖动转向；两端采用相同的拖动逻辑，松开后停止转向，不锁定鼠标指针。方向键也可转向，右上角 ↺ 或 Home 恢复当前阶段的默认视角；俯视阶段的触屏与键盘操作同样受旋转范围限制。
- 对局中轮到其他玩家或 AI 行动时，镜头会在前 0.6 秒逐渐加速、后 0.4 秒逐渐减速，平滑起步并在 1 秒时对准该角色、停止转动，摄像机位置保持不动。按住拖动或使用方向键会立即暂停自动对准，停止操作 1 秒后从当前视角重新开始这段对准过程；看牌、打开菜单、窗口失焦及牌局结束时暂停。轮到自己时，使用相同的 1 秒加速、减速曲线恢复到保存的玩家摄像机初始朝向；手动拖动同样可打断，停止操作 1 秒后恢复。
- 发底牌、翻牌、转牌、河牌以及公布结算结果前，服务器统一等待 **0.5 秒**；全下自动开完公共牌时也逐轮等待并发牌。发牌时镜头使用同样的 1 秒加速、减速曲线平滑回到保存的默认视角，拖动仍可中断。间隔及发牌期间不开放 AI 或玩家行动，也不消耗行动时间；牌张落定后才开放下一位行动并启动完整倒计时。重新连接会沿用当前发牌进度，不会重新开始计时。
- 人物标签使用 3D 场景内的广告牌，挂在角色头顶，始终面向摄像机；转头时与人物同步移出或进入视野。点击标签、人物或空椅即可操作，拖动不会触发入座或切换 AI。
- 菜单可查看牌型、切换合成提示音及 **高 / 中 / 低** 三档画质。声音初始关闭。高档为原标准画质；中档将整体 3D 渲染宽高各降低 10%（像素量减少约 19%），保留相同的 512×744 牌面贴图和纹理过滤精度，将阴影从 1024 降到 512，动态阴影最多每秒更新 15 次、静止时 2 次，自动分辨率最多再降低 5%，优先保证牌面可读；低档为原省电画质，关闭阴影、降低 3D 分辨率。画质选择立即生效并记住，旧的标准设置对应高档，旧的省电设置对应低档。**跟随其他行动玩家** 默认开启，可随时开关并记住选择；关闭后不再自动转向其他玩家，轮到自己时仍始终平滑回到保存的初始视角，发牌时的视角复位也保持启用。
- **帧率** 默认 **60 帧**，菜单可切换 **30 / 45 / 60 帧**，立即生效并记住选择。渲染节拍跟随显示刷新时序，后台页面暂停绘制，恢复后不补绘积压帧。人物、椅子的静态部件合并绘制，保留独立头部动画和编辑锚点；高档下牌和筹码移动时阴影最多每秒更新 30 次，静止时降至 4 次，动作结束立即刷新最终姿态；赢家文字动画最多每秒更新 30 次，空闲筹码跳过重复计算。手机高画质的初始 3D 像素比上限为 1.5，画面缓冲最多约 90 万像素，电脑约 140 万像素；中画质在此基础上将像素比乘以 0.9，手机上限为 1.35、约 72.9 万像素；持续掉帧时渐进降低 3D 分辨率，稳定后缓慢恢复，HTML 文字、头像栏与按钮不受影响。场景编辑器保持原来的预览精度与阴影更新。实际帧率受设备性能、显示刷新率和画质设置影响，可搭配中、低画质使用。
- 房主可随时在右上角菜单选择“关闭房间并返回主菜单”，立即停止当前牌局并解散房间；其他玩家会收到通知并一起返回主菜单，无需等本手结算。
- 多人局行动可设 15 / 30 / 60 秒；仅一名真人的桌子另可不限时。
- AI 与玩家使用相同的回合时限，均按房间规则显示 15 / 30 / 60 秒倒计时或不限时。发牌结束、轮到 AI 后立即开始计算；每次行动至少保留 **1.5 秒**，让镜头完成 1 秒的自动转向。计算不足 1.5 秒时补足剩余时间，超过则算完直接提交，不再添加随机等待。实际计算耗时取决于难度、对手数量、局面和服务器计算速度。所有难度均模拟仍在牌局中的全部对手，结合公开的下注记录、底池赔率、边池资格、位置和有效筹码选择跟注与加注；普通和困难难度使用更多模拟、减少随机误差。AI 只使用自己的手牌与公共信息。
- 超时：可过牌则过牌，否则弃牌；断线不会自动跟注或全下。
- 刷新页面后凭当前标签页内的匿名会话重连。昵称不是身份凭证；每个不同浏览器标签页可使用独立身份。
- 房主关闭浏览器时，可由其他在线真人接任房主；关闭运行服务的终端会中断整个游戏。

## 实现与验证

客户端：Three.js、DOM/CSS、原生 WebSocket。场景、人物、桌面、道具与手部均为程序生成 3D 模型及本地纹理，没有运行时外部美术依赖。

服务端：Node.js、ws，统一管理牌堆、行动、计时、边池与筹码。服务器不会向玩家或 AI 下发其他人的隐藏底牌。洗牌使用 `crypto.randomInt`，AI 只接收自己席位可见的信息。

运行自动化测试：

```pwsh
npm test
```

测试覆盖规则边界、1,000 次随机牌局、真实 WebSocket 的八人入座与抢座、权限、隐藏底牌、重复行动、会话重连，以及 1 真人 + 7 AI 的结算与重开。

当前运行边界：

- 房间保存在服务内存中；服务重启不会恢复之前的牌局。
- 3D 场景需要 WebGL 2；不支持时给出提示，规则与牌桌界面仍可操作。
- 模型为首版风格化程序模型，牌张已有独立的 3D 发牌 / 翻牌动画，角色尚未使用精细骨骼发牌动画。
- 已进行桌面浏览器的手机尺寸检查；实际手机性能仍需真机验证。

项目结构：`client/` 场景及界面，`server/` 联机和 AI，`shared/` 规则，`tests/` 自动验证。原始需求与策划见同目录的《游戏策划.md》。
